# Answer Correctness 판정 지침 (Claude 판정자용)

프로토타입 `D:\Project\Q&A\AgenticRAG\tools\ac_judge_guide.md` 와 같은 규칙이다. 파일 경로만 이 프로젝트 것으로 바꿨다.

입력: `D:\Project\DecideRag\eval\ac\packets_<회차>_<NN>.jsonl` — 한 줄에 묶음 하나.
`{"pid", "question", "answer", "reference"}`
- `question` 은 멀티턴이면 `[이전 대화] … [현재 질문] …` 형식이다. 대상은 **현재 질문**이다.
- `reference` 가 정답이다. 근거 문서는 주지 않는다. **답을 정답과만 비교**한다. 외부 지식으로 정답을 고치지 않는다.
- 어느 시스템의 답인지는 알려 주지 않는다. 묶음마다 독립적으로 판정한다.

출력: `D:\Project\DecideRag\eval\ac\verdicts_<회차>_<NN>.jsonl` (packets 파일과 같은 번호) — 묶음마다 한 줄, 입력과 같은 순서.

```json
{"pid": "a0001",
 "tp": [{"statement": "본인 결혼 시 휴가는 5일이다"}],
 "fp": [{"statement": "경조금은 30만원이다"}],
 "fn": [{"statement": "본인 결혼 경조금은 50만원이다"}]}
```

## 방법 (RAGAS Answer Correctness 의 사실 분류)
1. `answer` 를 사실 문장으로 쪼갠다. 한 문장에 확인 가능한 사실 하나(숫자·조건·대상·기간·승인자·결론 하나씩).
2. `reference` 도 같은 방식으로 사실 문장으로 쪼갠다.
3. 분류:
   - **tp**: 답의 사실 중 정답의 사실과 **같은 내용**인 것 (표현이 달라도 뜻이 같으면 tp).
   - **fp**: 답의 사실 중 정답과 **어긋나거나**, 정답에 **없는** 것.
     정답에 없는 덧붙임도 fp 다 (RAGAS 정의). 다만 근거 번호 `[1]`, "문서에 따르면" 같은 군말, 질문을 되풀이한 말은 사실이 아니므로 아예 넣지 않는다.
   - **fn**: 정답의 사실 중 답에 **빠진** 것. 답이 같은 항목을 **틀린 값**으로 말했으면, 답의 틀린 사실은 fp, 정답의 맞는 사실은 fn 으로 둘 다 넣는다.
4. 답이 거절("찾을 수 없습니다")뿐이면 `tp: []`, `fp: []`, 정답의 사실은 모두 `fn`.
   맞는 답 뒤에 거절 문장이 붙어 있으면 거절 문장은 무시하고 앞의 답만 판정한다.
5. 추론 문항: 정답의 결론(예: "70만원 지급")은 그 자체로 사실 하나다. 답의 결론 숫자가 다르면 fp + fn 이다.
   중간 계산식이 맞고 결론이 틀리면, 맞는 중간값은 tp, 틀린 결론은 fp, 정답 결론은 fn.
6. 중국어 등 다른 언어로 쓴 답도 내용으로 판정한다.

## 공통
- 엄격하고 일관되게. tp 는 정말로 같은 사실일 때만.
- 모든 pid 를 빠짐없이 출력한다. JSON 한 줄에 하나, 다른 글은 쓰지 않는다.
- 판정자 여럿이 동시에 일한다. 임시 파일은 반드시 자기 전용 하위 폴더에만 만들고, 공용 폴더의 다른 파일은 열지 않는다.
- 다 쓴 뒤 `python D:\Project\DecideRag\eval\ac.py check <packets 파일> <verdicts 파일>` 로 확인하고, `문제 0 건` 이 될 때까지 고친다.
